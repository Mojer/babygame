# 屍潮超載（Zombie Overload）— Phase 1+2 原型

超大量殭屍生存 × 連鎖清場。驗證兩件事：**效能**（數千殭屍在網頁上能不能穩定 60 FPS）和**爽感**（連鎖清場好不好玩）。PixiJS 8、TypeScript、Vite，美術全部是程式畫的佔位圖。

```sh
npm install
npm run dev     # http://127.0.0.1:5173
npm test        # 模擬層測試（網格、連鎖終止、流場繞路、可重現）
npm run bench   # 無頭壓測：不開瀏覽器量模擬層成本
npm run build
```

> 需要 Node 18 以上（本機 nvm 的 v22 可用）。

## 操作

| | 電腦 | 平板／手機（橫向） |
|---|---|---|
| 移動 | WASD／方向鍵 | 左半邊浮動搖桿 |
| 衝刺（無敵） | Space | 右下小按鈕 |
| 大招 | E | 右下大按鈕「星艦」或「巨砲」（充滿會發光） |
| 升級三選一 | 1／2／3 或滑鼠 | 點卡片 |
| 暫停／效能面板／靜音 | Esc／`／M | 右上按鈕 |

攻擊與技能全自動，只有**大招**由玩家決定時機。開始遊戲後的選擇頁可選兩種終極武器（或網址 `?ult=ship|pylon`）：

- 🚀 **星艦砲擊**：戰艦從畫面一角斜飛到對角（速度曲線兩端快、中央慢但不停），經過主角上空時往地面發射一圈擴散到整個畫面的衝擊波。
- ⚡ **天降巨砲**：巨型武器從外太空墜落、插進主角前方地面，落地重擊後朝 360° 連續散射 7 輪砲彈（每輪 24 發、逐輪錯開角度），砲彈貫穿、每隻每發只打一次，掃平整個畫面（`SKILLS.ult.pylon`）。

兩者都會清掉整個畫面的殭屍，凍結與不穩定的殭屍會一起碎裂、殉爆。

## 起始畫面與音樂

流程：封面（主視覺 `src/assets/title-bg.jpg` 露出，標題左上、左下選單：開始遊戲／玩法說明／音樂音效，↑↓＋Enter）→ 選擇角色＋終極武器（同一頁同時看到兩個角色與兩種武器；←→ 角色、↑↓ 武器、Enter 出發、Esc 返回）→「出發」進入遊戲。UI 風格參考 Typo Kart：深藍底、粗斜體標題、黃色重點、斜切卡片與按鈕、分段能力條。遊戲畫面與 HUD 在出發前完全不顯示。背景音樂 `public/audio/bgm_undead_rising.mp3`（Zombie Apocalypse — The Undead Rising (Instrumental)），開始遊戲才播放、循環、暫停時停止、跟著靜音（M）。

## 角色

開始畫面選角（點卡片或 ←／→、1／2 切換，Enter 開始，會記住上次選擇；網址 `?char=akane|yu` 可直接指定）。差異只有三項，技能與升級全部共用（`src/sim/characters.ts`）：

| | 茜（重砲少女） | 宇（機槍少年） |
|---|---|---|
| 基本攻擊 | 範圍爆破砲：每 0.75 秒一發，命中爆炸（半徑 30、12 傷害，算爆炸、能碎裂凍結殭屍） | 輕機槍：每 0.14 秒一發、單發 3.2、射程 240，一次一隻 |
| 血量 | 90 | 125 |
| 移動 | 82 | 68 |

角色素材只以 `art_spike/ref/` 的三視圖當人物參考（武器另外設計）生成：各自側面／朝下／朝上 × 4 格跑步（`proc/akane2`、`proc/yu2`、`proc/*_dirs`），依移動方向切換、頭像（選角與 HUD）、砲彈／曳光彈與命中爆光。

### 茜的造型：側掛重砲

大砲用粉紅背帶斜背在身側、砲管水平，兩手分別抓砲身上方的前提把與後提把。素材 `prompts/akane_sling_*_level.txt`（過程版本：兩手提在腰下、砲口朝下、砲口朝上，都保留在 `art_spike/gen/`）。生成圖的砲管會越過格線，先用 `relayout_by_ownership.py` 依連通區塊歸屬重排再切格。

## 最終波與結算

10:00 到了不會直接結束：主角周圍一圈生出 10 隻巨大變異體（加上場上原本的，約 20 隻），血量 ×0.6、一般殭屍半速持續生成（沒有屍潮），HUD 計時改成「FINAL 巨大變異體 ×N」。全部擊倒後剩下的殭屍一起炸掉、黃色 **FINISH!** 斜帶切入，3.2 秒後進結算頁（`FINAL` in `content.ts`）。

結算頁延續封面／選角的風格：角色展示台＋評等（S/A/B/C/D）、分數、存活時間／最終波用時／擊殺／變異體／最大連鎖／等級／終極武器次數（數字跑動）、本局強化。「再來一局」（Enter）直接回選角頁、「主選單」（Esc）回封面。倒下時同一頁顯示 GAME OVER。

## 巨大變異體（小 Boss）

第 90 秒起每 70 秒嘗試生成一隻（同時上限隨時間增加）；**第 5 分鐘後**間隔從 30 秒逐漸縮到 10 秒、上限每分鐘 +2、一次最多來 3 隻（bot 實測場上同時存活約 1→2→3→5→8 隻），血量 420 × 時間倍率、接觸傷害高。**不會被凍結、吸入黑洞或被引爆**，只能硬打；頭上有血條，出現時有警告橫幅，倒下會大爆炸並噴出一圈經驗。素材 `prompts/mutant.txt`，以殭屍圖當風格參考生成。

## 玩法核心：狀態 × 反應

技能只負責「附加狀態」或「造成觸發」，反應表（`src/sim/reactions.ts`）決定組合結果：

| 狀態 | 觸發 | 反應 |
|---|---|---|
| ❄️ 凍結（冰晶崩裂） | 爆炸、光束、冰片、衝擊波 | **碎裂**：即死＋噴冰片，冰片再碎裂旁邊凍結的 → 骨牌 |
| ☣️ 不穩定（被毒爆波及） | 光束、衝擊波 | **引爆** |
| ☣️ 感染核心死亡 | — | **毒爆**：範圍傷害＋讓周圍最多 10 隻變不穩定 |
| 不穩定的殭屍死亡 | — | **殉爆** |
| 🌀 被黑洞吸住 | 黑洞結束 | **坍縮**：吸越多炸越大 |

反應會**消耗**狀態，同一隻殭屍不會被重複引爆；連鎖事件延遲 40–130ms 一跳，畫面上是波浪擴散，運算也攤到多幀。殉爆傷害刻意低於感染核心血量，避免密集屍群自己無限連鎖——大連鎖要靠玩家把冰凍、黑洞、光束、超載組合起來。

每條連鎖有自己的 id（`ChainTracker`），從根（碎裂／毒爆／坍縮／星艦掃蕩）開始計數，`CHAIN ×N` 顯示的是單一條連鎖，不是一段時間內的總擊殺。

## 美術風格：3/4 斜俯視（風格驗證中）

預設是 3/4 斜俯視 Q 版像素風：角色正面朝鏡頭、依 y 排序繪製（越下面越前面）、左右翻轉表示方向、腳下有影子。網址加 `?style=topdown` 可切回原本程式畫的 90° 俯視佔位圖比較。

素材流程（`art_spike/`）：

1. `prompts/*.txt` → 透過 generate2dsprite / generate2dmedia 的 `route_media.py` 生成（目前路線：本機 Codex CLI）→ `gen/`
2. `generate2dsprite.py process` 去背、切格、腳底對齊 → `proc/`
3. `python art_spike/pack_sprites.py`（Python 3.10+、numpy、Pillow）：面積縮小到遊戲尺寸（普通殭屍 26px、主角 28px）、二值 alpha、全角色共用 64 色調色盤，產生受擊白／冰凍／屍體變體，打包成 `public/sprites/horde.png`；爆炸黑底轉 alpha → `explosion.png`

地圖（同一套流程，generate2dmap 的 `extract_terrain_tiles.py`（無縫檢查）與 `extract_prop_pack.py`）：

- 地面：4 種 128px 無縫地磚（廣場石板、柏油、人行道、屋頂），道路標線與斑馬線用程式畫，烘進地面 chunk。
- 外圍建築：屋頂地磚 + 底邊一排 64px 立面模組（4 種店面／公寓），立面底邊就是碰撞邊界。
- 有高度的物件（車輛、事故車、花台、長椅、垃圾桶、路障、路燈、消防栓、木箱、三角錐、推車、噴水池）放在角色圖集裡，和殭屍、主角一起依 y 排序，可以互相遮擋。
- 噴水池的碰撞改成扁橢圓（`map.ts` 的 `fountain.ry`），和 3/4 畫面上的水池外緣一致。
- 主角參與排序（會被前面的殭屍與物件擋住）；只有腳下的青色光圈畫在最上層，被淹沒時找得到自己。

仍是佔位：黑洞、冰晶、光束特效與介面。

## 測試參數

| 參數 | 作用 |
|---|---|
| `?n=3000` | 同屏上限（覆寫品質分級） |
| `&stress` | 開局直接補滿上限，死多少補多少 |
| `&skills=0` | 關閉自動技能（純屍群壓測） |
| `&god` | 無敵 |
| `&bot` | 自動玩家（避屍群、撿寶石、適時放大招），開局自動開始 |
| `&auto` | 升級自動選 |
| `&fx=low\|mid\|high` | 鎖定品質分級（不鎖會依幀時間自動降級） |
| `&t=240` | 從第 4 分鐘開始（血量與生怪速率對應該時間） |
| `&seed=42` | 固定亂數，結果可重現 |
| `&perf` | 顯示效能面板（預設隱藏；遊戲中按 ` 也可切換） |
| `&style=topdown` | 改用 90° 俯視佔位圖 |
| `&char=akane\|yu` | 預先選定角色 |

實機壓測建議：`?n=1000&stress&god&skills=0&fx=mid&bot` 放著跑 8 分鐘看效能面板的 p95（手機熱降頻後的數字才準）。

除錯：console 裡 `__zo.world`、`__zo.gr` 可以直接檢查狀態。

## 架構

```
src/
  sim/        純邏輯，不依賴 Pixi，可在 Node 跑（bench/tests 直接用）
    content.ts    所有數值（調難度、調效能預算改這裡）
    world.ts      固定 60Hz 步進：玩家 → 網格 → 流場 → 殭屍移動 → 技能 → 連鎖 → 生怪
    zombies.ts    SoA 資料池：每個欄位一條 typed array，swap-remove，不為殭屍配置物件
    grid.ts       均勻網格，每 tick counting sort 重建；範圍查詢、最近目標、密度
    flowfield.ts  以玩家為源的距離場（Dial's algorithm）＋ Sobel 方向場，全圖重算 < 0.5ms
    chain.ts      連鎖事件佇列（延遲、每 tick 預算、深度上限）＋ 連鎖追蹤
    reactions.ts  狀態 × 反應表
    map.ts        都市廣場佈局與障礙物格子
    bot.ts        自動玩家
  render/     Pixi 8，只讀 sim 狀態
    renderer.ts   世界先畫到低解析度 RenderTexture，再整數倍放大（像素風＋填充率省 9～16 倍）
    chunks.ts     地面切 256² chunk；血跡、屍體、焦痕直接烘進地面，之後零成本
    fx.ts         視覺粒子，固定上限（死再多隻也不會爆特效）
    lens.ts       黑洞重力透鏡（低解析度後處理）
    sprites.ts    3/4 風格圖集載入（public/sprites/）
    atlas.ts      程式繪製的像素圖集（90° 佔位角色、特效粒子、影子）
    mapPainter.ts 90° 佔位地圖繪製（style=topdown）
    mapPainterOblique.ts 3/4 地圖：地磚、道路標線、建築屋頂＋立面
  ui/         HTML HUD、雙拇指輸入、效能面板（含自動降級）
  audio/      WebAudio 合成音效＋發聲數限制
```

殭屍本體用 `ParticleContainer` + `Particle` 繪製（不是 Sprite）；所有特效貼圖與殭屍共用同一張圖集。

## 目前量到的數字（M 系列 Mac）

| 項目 | 數值 |
|---|---|
| 模擬層 5,000 隻 | 0.9ms／tick（`npm run bench`） |
| 模擬＋渲染（含 GPU，`gl.finish`）3,000 隻 | 0.5ms + 0.2ms／幀 |
| 一局 10 分鐘（自動玩家，5 個 seed） | 全部存活、約 3 萬擊殺、後期同時 600～1,000 隻、Lv 37～43、連鎖中位數約 60、最大 1,000～1,700 |

手機 CPU 大約是這台的 1/3～1/5，**真實裝置數字還需要實機壓測**。

## 已知待調整

- 後期偏簡單（自動玩家 4 分鐘後幾乎不掉血）；前 2 分鐘偏難。數值都在 `content.ts`。
- 寶石超過 600 顆會合併成大顆，一次撿到可能連升好幾級。
- 南側建築在 3/4 視角下看到的是屋頂（立面朝外），西／東兩側是一段段屋頂加立面；屋頂細節偏少。
- 直放的車只有紅色一種正面圖。
- `?skills=0` 會關掉所有自動攻擊（只供壓測），畫面會提示。
- 走路每種只有 4 格（一排生成 4 格），即時播放的流暢度還沒實際確認；正式版建議 6–8 格。
- Boss、角色、存檔、結算獎勵尚未做（依企劃，核心戰鬥驗證後再加）。
